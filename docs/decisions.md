# Design decisions

One line per decision: decision — reason — rejected alternative.

- uv + pyproject.toml for packaging — reproducible `uv.lock` and fast installs; `pip install -e .` still works from pyproject as a fallback — rejected: requirements.txt + pip-tools, Poetry.
- FastAPI + Pydantic v2 — the same models validate stage boundaries and generate the OpenAPI docs, so schemas double as API documentation — rejected: Flask + marshmallow, hand-written JSON schemas.
- No agent framework; a fixed plan → validate → execute pipeline — explicit control flow, the LLM only emits a QueryPlan, smaller hallucination surface, easy to test deterministically — rejected: LangChain/LlamaIndex agents with tool calling loops.
- No database server — data comes live from the ClinicalTrials.gov API and there is no persistent business data; a local cache (SQLite/file) sits behind an interface, with Postgres/AACT as the production path for heavy aggregation — rejected: running Postgres/AACT from day one.
- Drug match mode defaults to exact `AREA[InterventionName]`, with an opt-in broad mode (`query.intr`) — 336 / 2981 pembrolizumab hits under `query.intr` mention the drug only in text or comparator arms — rejected: `query.intr` as the default.
- Multi-phase trials get their own bucket (e.g. "Phase 1/Phase 2") and phase buckets are mutually exclusive — per-phase counting overlaps, so totals would exceed the number of trials — rejected: counting a trial in every phase it lists.
- Missing phase goes to an "Unknown" bucket and `NA` to a "Not Applicable" bucket, and the two are never merged — missing means non-interventional/unknown, while `NA` is an explicit interventional value — rejected: one combined "No phase" bucket.
- Countries are reported as the API gives them (trimmed) and deduplicated within a study; territories are not rolled up — the vocabulary is already clean, and rolling up is a product decision we would hide from the user — rejected: mapping Puerto Rico, Guam, etc. into a parent country.
- Dates are bucketed by year or month only; a missing date type is "unknown"; estimated dates are flagged, not excluded — month-only dates are indexed as the first of the month, so finer ranges mis-assign silently, and 266 past dates are still marked ESTIMATED — rejected: day-level ranges, and dropping estimated dates.
- Interventions are grouped by MeSH term when present and the raw name is cited; condition MeSH is not used for grouping — condition MeSH contains spurious terms (e.g. Parkinson Disease 4 on cancer trials) — rejected: grouping conditions by derived MeSH.
- Intervention↔MeSH linking is not attempted; grouping uses the study-level `derivedSection.interventionBrowseModule.meshes` list (id + term, no ancestors or browseLeaves), and citations give the MeSH term and the study's raw intervention names side by side, with no inferred link — the API provides MeSH at study level only; exact-name matching misses common forms like "pembrolizumab (KEYTRUDA®)", and substring matching produces false merges (e.g. biosimilars); study-level MeSH is enough for grouping drugs and building network nodes, both per-trial sets — rejected: exact-name or substring linking per intervention.
- MeSH id (`InterventionMeshId`) is part of the retrieval projection — terms can be renamed, while ids such as C582435 are stable — rejected: storing the term only.
- Full-fetch cap of 10,000 records; beyond that, results are truncated and coverage is reported in meta — keeps latency and API load bounded (about 10 pages) — rejected: unbounded fetches, and silent truncation.
- Client-side rate limiting (about 1 request / 1.2 s) with exponential backoff; page requests resend frozen params; the retrieved count must reconcile with totalCount — the API returns 429 with no Retry-After header after about 10 rapid requests, and page tokens are not bound to the query — rejected: relying on server-side limits, and rebuilding params per page.
- Aggregation returns a `GroupResult` (buckets + `buckets_overlap`) instead of a bare list — overlap is a property of the whole result and has to reach meta — rejected: `list[Bucket]` with overlap recomputed in spec.
- A missing value uses the bucket key "Unknown", which is distinct from the API's own `UNKNOWN` enum value (Status, AgencyClass) — the API's UNKNOWN is a reported value, not missing data — rejected: mapping both to one bucket.
- Country citations quote the raw API string and the index of the first location listing that country (`locations[i].country`); the trimmed name is only the bucket key — invariant 2 requires the exact source value — rejected: citing the trimmed name at `locations[].country`.
- A year-only start date ("2026") is parsed as January 1 with precision "year"; it counts for `start_year` but goes to `Unknown` for `start_month` — placing it in January would invent a month — rejected: rejecting the record, and bucketing it as January.
- Normalize raises `SourceRecordError` for unknown enum values, malformed dates and nameless interventions or MeSH entries — guessing would corrupt counts silently, and skipping list entries would shift citation indices — rejected: coercing to None, and skipping entries.
- Enrollment bins: 0, 1-49, 50-99, 100-499, 500-999, 1000+, with ESTIMATED counts flagged — readable bins covering phase 1 through phase 3 trial sizes; stated in meta assumptions — rejected: quantile bins, which change with every query.
- Chart compatibility is defined once by dimension kind (categorical, temporal, binned) in `spec/chart.py` and reused by the plan validator — the validator and chart selection cannot disagree — rejected: separate rule sets per stage.
- Network edges cite only the primary values of their endpoints; drug nodes also carry the raw intervention names as supporting citations — an edge is defined by its endpoints, and the context names stay on the node — rejected: copying supporting citations onto every edge.
- Intervention names in `AREA[InterventionName]` are always double-quoted, and names containing `"` are rejected — unquoted, "pembrolizumab (KEYTRUDA®)" is parsed as grouping (559 hits vs 43), and an escaped quote matched nothing — rejected: quoting only multi-word values, and stripping quotes.
- `query.cond`/`query.spons`/`query.locn` values are sent raw, and values containing Essie syntax (`"`, `()`, `[]`, standalone uppercase AND/OR/NOT) are rejected with a structured error; the semantics are stated in `meta.search_semantics` — raw keeps the API's synonym expansion (NSCLC: 8601 raw vs 8078 as a quoted phrase), and rejecting syntax stops users or the LLM from changing search semantics by accident — rejected: quoting every value as a phrase.
- A count that does not reconcile with totalCount is flagged (`FetchResult.reconciled=False`, meta warning) rather than raised — the API refreshes daily and can shift during pagination; the chart is still useful when the gap is stated — rejected: a ReconciliationError that fails the whole request.
- Studies are deduplicated by NCT ID across pages, and duplicates are counted in meta — page tokens are not bound to a query, so a repeated record would inflate counts silently — rejected: trusting pages to be disjoint.
- Every page sends identical params, including `countTotal=true` (ignored after page 1) — a single frozen param set is easy to verify and the token cannot be mixed with other params — rejected: sending countTotal on page 1 only.
- The response cache works per page (key = URL + sorted params); when page 1 is a hit, later pages must be hits too, otherwise the fetch restarts live — mixing a cached token with a live fetch could silently return a different result set — rejected: caching only whole fetches, which needs a second key scheme.
- `top_n` keeps the N known buckets with the most trials (union of cohorts, ties in display order) plus the Unknown bucket, with no "Other" bucket, and reports the omitted keys and the trials visible only in omitted buckets — an "Other" count is correct only for mutually exclusive dimensions (it would double-count for countries or conditions); it could be added later for exclusive dimensions only — rejected: an "Other" bucket for every dimension.
- `top_n` with a relation is rejected by the validator — networks have no buckets, and trimming nodes would need its own rules for orphaned edges — rejected: silently ignoring top_n.
- Grouped results across cohorts share one key order, computed by `group_by` over the deduplicated union of trials — reuses the dimension's own ordering rules (rank, key or count) without exposing ranks — rejected: merging per-cohort orders, which cannot recover phase rank order.
- Response encoding uses Vega-Lite-style channels, and networks use Cytoscape-style `{data: ...}` elements with edge ids `<source>--<target>` — renderer-neutral vocabularies most clients already know — rejected: a custom encoding format.
- `meta.interpretation` holds the question, the executed plan and `planned_by` ("llm", "rules" when no LLM is configured, or "structured_fields" when code passes a plan to the pipeline directly), plus the model, draft, overrides and rejected drafts for LLM plans — the reader must know whether and how the question text was interpreted — rejected: echoing only the plan.
- Records that fail normalization are skipped and listed by NCT ID in meta warnings, with a per-cohort `records_skipped` count — one malformed record must not fail a request over thousands — rejected: failing the request, and dropping records silently.
- Network node sizes are flagged as overlapping (`buckets_overlap=true`) — a trial counts toward its sponsor and every drug it lists — rejected: reporting false because a graph has no buckets.
- Settings come from environment variables (prefix CTVIZ_) via pydantic-settings, which is already a dependency — one typed place for the cap, pacing, retries and cache — rejected: module constants.
- Live tests are excluded by default (`addopts = -m 'not live'`) and run with `pytest -m live` — the default suite stays offline and deterministic — rejected: an environment-variable switch.
- Start dates with no ACTUAL/ESTIMATED type are counted in their period and reported per bucket and in total (`unknown_date_type_count`) with a warning; trials with no start date at all stay in Unknown and are not counted again — 41 of 2518 pembrolizumab trials starting 2015+ are legacy records without a type, and per-bucket counts let a chart style uncertain periods — rejected: treating untyped dates as actual without saying so, and excluding them.
- Dimensions have a separate `title_label` for chart and axis titles ("start year") while `label` stays in warnings ("start date") — the title must state the granularity, but warning text is about the source field — rejected: renaming `label`, which changes warning text.
- The planner uses OpenAI structured outputs (`chat.completions.parse` with a strict JSON schema generated from the Pydantic `LlmPlanDraft`) — the model can only return a schema-valid draft with enum-typed dimensions, relations, phases and statuses, so free-text parsing and invented field names are impossible and validation errors are about meaning, not syntax — rejected: JSON mode plus manual parsing, and function calling with a hand-written schema.
- The system prompt is rendered from the registry (`DimensionSpec.description`, `RelationSpec.description`), `spec/chart.py` (`CHART_DESCRIPTIONS`, `CHARTS_BY_KIND`) and the API enums, and the few-shot examples are `LlmPlanDraft` instances checked by a test — a new dimension reaches the prompt with no prompt edit, and the prompt cannot offer something the code does not support — rejected: a hand-written prompt file.
- Explicit structured fields in the request always override the LLM's reading; an explicit filter applies to every cohort, an explicit dimension clears the LLM's relation (and vice versa), and every replaced value is listed in `interpretation.overrides` and `meta.assumptions` — the caller's explicit choice is the most reliable signal, and overriding silently would hide a disagreement between question and fields — rejected: LLM wins, and rejecting requests where the two disagree.
- No agent loop: one structured draft, and one retry carrying the validation error, then a structured `planning_failed` error — planning is a single translation step whose output is fully checked by deterministic code; a loop adds latency and cost without new information and makes failures harder to reproduce — rejected: tool-calling agents that iterate until a plan passes, and unbounded retries.
- The LLM answers in a separate `LlmPlanDraft` schema with `unsupported_reason` and `clarification`, and cohort labels are derived in code from the merged filters — the model needs a sanctioned way to decline or ask instead of forcing a plan (invariant 7), and labels shown in charts should not be LLM text — rejected: emitting `QueryPlan` directly, and LLM-written cohort labels.
- An `unsupported_reason` or `clarification` returns a structured 422 error even when explicit fields are present — the model judged the question itself unanswerable or ambiguous, and fields cannot be trusted to resolve that silently — rejected: ignoring the decline when fields allow a plan.
- Without an LLM, a request with `query` only is an `llm_not_configured` error, while a request with any structured field is validated as written (missing grouping stays `no_dimension_or_relation`) — only a query-only request needs interpretation; partial structured requests already have a precise error — rejected: `llm_not_configured` for every request without a grouping.
- Cohorts with the same label or identical filters are rejected by the validator — results are keyed by label, and an explicit filter applied over an LLM comparison (e.g. `drug` over "A vs B") would otherwise collapse it into two identical series — rejected: deduplicating cohorts silently.
- The LLM client is built at app startup, and a non-ASCII or whitespace-padded `OPENAI_API_KEY` raises a ValueError there without echoing the key — a placeholder key otherwise fails inside the SDK on every request with a bare UnicodeEncodeError (an unstructured 500) — rejected: building the client at import time, and failing per request.
- PyYAML is a declared dev dependency, used only by `scripts/eval_planner.py` to read `tests/eval/questions.yaml` — the eval set is easier to review as YAML; PyYAML was already installed transitively by `uvicorn[standard]`, so declaring it adds nothing new — rejected: JSON for the eval set, and relying on the transitive install.
- The planner eval compares filter strings case-insensitively and cohorts order-insensitively, and counts any filter that was not expected as a miss — case does not change the registry search, while an invented filter changes the result set — rejected: exact string comparison, and scoring only the expected keys.
- Ranking questions without a number ("which countries have the most ...") get `top_n` from `DEFAULT_TOP_N_FOR_RANKING` (15): the LLM only flags `ranking_intent`, code picks the number, a number from the question or request wins, relations are never trimmed, and meta states the default and how many buckets were omitted — showing 65 countries does not answer "which have the most", but a number chosen by the LLM would be an invented parameter (invariant 1) — rejected: letting the LLM choose top_n, and leaving ranking questions untrimmed.
- Temporal buckets whose period starts after as_of are flagged `is_future` on the bucket and datum, with one warning naming the trials and the first future bucket; `incomplete` still marks only the current period — planned (estimated) start dates are projections, and a chart that shows them like past activity overstates future growth — rejected: dropping future buckets, which hides registered trials, and reusing `incomplete` for them.
- The LLM sits behind an ordered fallback chain (`LLM_FALLBACK_CHAIN`, default `openai:gpt-4.1-mini`) of `OpenAICompatibleProvider`s; a provider without a key is skipped at startup with a log line, and only infrastructure failures (timeout, connection error, 429, 5xx after the SDK retry) move to the next provider — the same question that fails validation would most likely fail the same way on another model, so validation failures keep the retry-with-error path, and switching would hide a prompt problem behind a provider change; the answering provider, model, response mode and fallback reason are in `meta.interpretation` — rejected: switching providers on any failure, and a per-provider SDK abstraction (both providers speak the OpenAI chat API).
- DeepSeek is asked in `json_object` mode with the JSON schema embedded in the system prompt; OpenAI keeps strict `json_schema` — a live probe on 2026-10-17 got HTTP 400 "This response_format type is unavailable now" for strict `json_schema` from DeepSeek, while `json_object` returned a schema-valid answer; `validate_plan` guards both modes — rejected: dropping DeepSeek, and tool calling as a schema substitute.
- `meta.interpretation.model_used` is the model the provider reports, not the configured name — DeepSeek served the configured `deepseek-chat` as `deepseek-flash`, and OpenAI reports the dated snapshot (`gpt-4.1-mini-2025-04-14`) — rejected: echoing the configured model name.
- Network nodes skip a small registry deny-list of exact intervention MeSH ids (`NETWORK_EXCLUDED_MESH`): comparators without active treatment (Standard of Care, Observation, Watchful Waiting, and Saline Solution, the term placebo arms map to) and observed mis-mappings that are not interventions; each excluded term, its reason and its trial count are in `meta.network` and `meta.assumptions` — matching by MeSH id is exact and stable, and the list only holds terms seen on live data (2026-10-18) — rejected: substring matching on free-text names ("placebo", "standard"), which misfires on names like "Paclitaxel (standard of care)", and `browseLeaves[].relevance == HIGH` as a data-driven filter, which the API lists in its schema but does not serve.
- Diagnostics and assessments (Specimen Handling, Magnetic Resonance Spectroscopy, Biopsy, imaging terms) are kept as nodes, like radiotherapy and surgery — a hand-curated list built from one drug's networks would not generalize to other drugs and would hide real study content; the node-type limitation is stated in meta instead — rejected: an observed deny-list of diagnostics.
- The "Taxes" (from "taxane") and "Automobiles" (from "CAR") intervention terms confirm that study-level MeSH is derived by automated text mapping, not curated per intervention: it is a grouping key with its raw names cited alongside, not an authoritative label — rejected: treating intervention or condition MeSH as ground truth.
- Network nodes keep type `drug` for every intervention MeSH term, and meta says the API gives no per-term intervention type — interventionType is set per raw intervention and has no link to the study-level MeSH list, so any typing (e.g. "radiation" for Radiotherapy) would be a guess — rejected: inferring node types from MeSH term text or from the trial's intervention types.
- Networks are capped for readability with `MAX_NETWORK_NODES` (50) and `MIN_EDGE_WEIGHT` (2) from settings: edges below the threshold go first, then the highest-degree nodes over the remaining edges are kept with only the edges between them; omitted nodes and edges and the trials left without a shown edge or node are counted in `meta.network` and a warning; node sizes still count every trial; `build_network` itself defaults to no caps — the live pembrolizumab networks had 1640 nodes / 4527 edges (sponsor-drug) and 697 / 7713 (drug co-occurrence), 74-80% of edges with weight 1, at 5.8-7.9 MB; degree over thresholded edges stops one-off co-listings from ranking nodes — rejected: ranking by degree over all edges, recomputing node sizes after trimming, and reusing `top_n` (still rejected for relations).
- When a network response is over `NETWORK_MAX_RESPONSE_BYTES` (1 MB), edge citations are cut to `NETWORK_REDUCED_EDGE_CITATION_CAP` (2, i.e. both endpoints in one trial) and the sizes before and after are reported; edges are never dropped for size — after the caps the drug co-occurrence network was still 1.65 MB, almost all of it edge citations, and `citation_count_total` keeps the true count — rejected: dropping edges, and a search for the largest cap that fits (more code for little gain).
- The queried drug stays in drug co-occurrence networks as the hub — it is the answer's anchor ("with pembrolizumab"), and its edge weights are the numbers the question asks for; weights and sizes are computed as sets of distinct NCT IDs, so a trial listing a drug twice (alias entries share a MeSH id) counts once — rejected: removing the filter drug's node, and counting MeSH entries.
- Network nodes are ranked by weighted degree (sum of incident edge weights after the `MIN_EDGE_WEIGHT` cut), ties by size then label — plain degree rewards umbrella trials that list many drugs (dacomitinib, HhAntag691 and lorlatinib, 3-4 trials each, made the pembrolizumab top 50), while weighted degree rewards repeated co-occurrence, which is what "frequently" means — rejected: plain degree, and ranking by node size (which ignores the edges the chart shows).
