# Design decisions

One line per decision: decision — reason — rejected alternative.

- uv + pyproject.toml for packaging — reproducible `uv.lock` and fast installs; `pip install -e .` still works from pyproject as a fallback — rejected: requirements.txt + pip-tools, Poetry.
- FastAPI + Pydantic v2 — the same models validate stage boundaries and generate the OpenAPI docs, so schemas double as API documentation — rejected: Flask + marshmallow, hand-written JSON schemas.
- No agent framework; a fixed plan → validate → execute pipeline — explicit control flow, the LLM only emits a QueryPlan, smaller hallucination surface, easy to test deterministically — rejected: LangChain/LlamaIndex agents with tool calling loops.
- No database server — data comes live from the ClinicalTrials.gov API and there is no persistent business data; a local cache (SQLite/file) sits behind an interface, with Postgres/AACT as the production path for heavy aggregation — rejected: running Postgres/AACT from day one.
- Drug match mode defaults to exact `AREA[InterventionName]`, with an opt-in broad mode (`query.intr`) — 336 / 2981 pembrolizumab hits under `query.intr` mention the drug only in text or comparator arms — rejected: `query.intr` as the default.
- Multi-phase trials get their own bucket (e.g. "Phase 1/Phase 2") and phase buckets are mutually exclusive — per-phase counting overlaps, so totals would exceed the number of trials — rejected: counting a trial in every phase it lists.
- Missing phase goes to an "Unknown" bucket and `NA` to a "Not Applicable" bucket, and the two are never merged — missing means non-interventional/unknown, while `NA` is an explicit interventional value — rejected: one combined "No phase" bucket.
- Countries are reported as the API gives them (trimmed) and deduplicated within a study; territories are not rolled up — the vocabulary is already clean, and rolling up is a product decision we would hide from the user — rejected: mapping Puerto Rico, Guam, etc. into a parent country.
- Dates are bucketed by year or month only; a missing date type is "unknown"; estimated dates are flagged, not excluded — month-only dates are indexed as the first of the month, so finer ranges mis-assign silently, and 266 past dates are still marked ESTIMATED — rejected: day-level ranges, and dropping estimated dates.
- Interventions are grouped by MeSH term when present and the raw name is cited; condition MeSH is not used for grouping — condition MeSH contains spurious terms (e.g. Parkinson Disease 4 on cancer trials) — rejected: grouping conditions by derived MeSH.
- Intervention↔MeSH linking is not attempted; grouping uses the study-level `derivedSection.interventionBrowseModule.meshes` list (id + term, no ancestors or browseLeaves), and citations give the MeSH term and the study's raw intervention names side by side, with no inferred link — the API provides MeSH at study level only; exact-name matching misses common forms like "pembrolizumab (KEYTRUDA®)", and substring matching produces false merges (e.g. biosimilars); study-level MeSH is enough for grouping drugs and building network nodes, both per-trial sets — rejected: exact-name or substring linking per intervention.
- MeSH id (`InterventionMeshId`) is part of the retrieval projection — terms can be renamed, while ids such as C582435 are stable — rejected: storing the term only.
- Full-fetch cap of 10,000 records; beyond that, results are truncated and coverage is reported in meta — keeps latency and API load bounded (about 10 pages) — rejected: unbounded fetches, and silent truncation.
- Client-side rate limiting (about 1 request / 1.2 s) with exponential backoff; page requests resend frozen params; the retrieved count must reconcile with totalCount — the API returns 429 with no Retry-After header after about 10 rapid requests, and page tokens are not bound to the query — rejected: relying on server-side limits, and rebuilding params per page.
- Aggregation returns a `GroupResult` (buckets + `buckets_overlap`) instead of a bare list — overlap is a property of the whole result and has to reach meta — rejected: `list[Bucket]` with overlap recomputed in spec.
- A missing value uses the bucket key "Unknown", which is distinct from the API's own `UNKNOWN` enum value (Status, AgencyClass) — the API's UNKNOWN is a reported value, not missing data — rejected: mapping both to one bucket.
