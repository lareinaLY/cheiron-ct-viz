# Design decisions

One line per decision: decision — reason — rejected alternative.

- uv + pyproject.toml for packaging — reproducible `uv.lock` and fast installs; `pip install -e .` still works from pyproject as a fallback — rejected: requirements.txt + pip-tools, Poetry.
- FastAPI + Pydantic v2 — the same models validate stage boundaries and generate the OpenAPI docs, so schemas double as API documentation — rejected: Flask + marshmallow, hand-written JSON schemas.
- No agent framework; a fixed plan → validate → execute pipeline — explicit control flow, the LLM only emits a QueryPlan, smaller hallucination surface, easy to test deterministically — rejected: LangChain/LlamaIndex agents with tool calling loops.
- No database server — data comes live from the ClinicalTrials.gov API and there is no persistent business data; a local cache (SQLite/file) sits behind an interface, with Postgres/AACT as the production path for heavy aggregation — rejected: running Postgres/AACT from day one.
- Drug match mode defaults to exact `AREA[InterventionName]`, with an opt-in broad mode (`query.intr`) — 336 / 2981 pembrolizumab hits under `query.intr` mention the drug only in text or comparator arms — rejected: `query.intr` as the default.
- Multi-phase trials get their own bucket (e.g. "Phase 1/Phase 2") and phase buckets are mutually exclusive — per-phase counting overlaps, so totals would exceed the number of trials — rejected: counting a trial in every phase it lists.
- Missing phase goes to an "Unknown" bucket and `NA` to a "Not Applicable" bucket, and the two are never merged — missing means non-interventional/unknown, while `NA` is an explicit interventional value — rejected: one combined "No phase" bucket.
- Countries are reported as the API gives them (trimmed) and deduplicated within a study; territories are not rolled up — the vocabulary is already clean, and rolling up is a product decision we would hide from the user — rejected: mapping Puerto Rico, Guam, etc. into a parent country.
- Dates are bucketed by year or month only; a missing date type is "unknown"; estimated dates are flagged, not excluded — month-only dates are indexed as the first of the month, so finer ranges mis-assign silently, and 266 past dates are still marked ESTIMATED — rejected: day-level ranges, and dropping estimated dates.
- Interventions are grouped by MeSH term when present and the raw name is cited; condition MeSH is not used for grouping — condition MeSH contains spurious terms (e.g. Parkinson Disease 4 on cancer trials) — rejected: grouping conditions by derived MeSH.
- Intervention↔MeSH linking is not attempted; grouping uses the study-level `derivedSection.interventionBrowseModule.meshes` list (id + term, no ancestors or browseLeaves), and citations give the MeSH term and the study's raw intervention names side by side, with no inferred link — the API provides MeSH at study level only; exact-name matching misses common forms like "pembrolizumab (KEYTRUDA®)", and substring matching produces false merges (e.g. biosimilars); study-level MeSH is enough for grouping drugs and building network nodes, both per-trial sets — rejected: exact-name or substring linking per intervention.
- MeSH id (`InterventionMeshId`) is part of the retrieval projection — terms can be renamed, while ids such as C582435 are stable — rejected: storing the term only.
- Full-fetch cap of 10,000 records; beyond that, results are truncated and coverage is reported in meta — keeps latency and API load bounded (about 10 pages) — rejected: unbounded fetches, and silent truncation.
- Client-side rate limiting (about 1 request / 1.2 s) with exponential backoff; page requests resend frozen params; the retrieved count must reconcile with totalCount — the API returns 429 with no Retry-After header after about 10 rapid requests, and page tokens are not bound to the query — rejected: relying on server-side limits, and rebuilding params per page.
- Aggregation returns a `GroupResult` (buckets + `buckets_overlap`) instead of a bare list — overlap is a property of the whole result and has to reach meta — rejected: `list[Bucket]` with overlap recomputed in spec.
- A missing value uses the bucket key "Unknown", which is distinct from the API's own `UNKNOWN` enum value (Status, AgencyClass) — the API's UNKNOWN is a reported value, not missing data — rejected: mapping both to one bucket.
- Country citations quote the raw API string and the index of the first location listing that country (`locations[i].country`); the trimmed name is only the bucket key — invariant 2 requires the exact source value — rejected: citing the trimmed name at `locations[].country`.
- A year-only start date ("2026") is parsed as January 1 with precision "year"; it counts for `start_year` but goes to `Unknown` for `start_month` — placing it in January would invent a month — rejected: rejecting the record, and bucketing it as January.
- Normalize raises `SourceRecordError` for unknown enum values, malformed dates and nameless interventions or MeSH entries — guessing would corrupt counts silently, and skipping list entries would shift citation indices — rejected: coercing to None, and skipping entries.
- Enrollment bins: 0, 1-49, 50-99, 100-499, 500-999, 1000+, with ESTIMATED counts flagged — readable bins covering phase 1 through phase 3 trial sizes; stated in meta assumptions — rejected: quantile bins, which change with every query.
- Chart compatibility is defined once by dimension kind (categorical, temporal, binned) in `spec/chart.py` and reused by the plan validator — the validator and chart selection cannot disagree — rejected: separate rule sets per stage.
- Network edges cite only the primary values of their endpoints; drug nodes also carry the raw intervention names as supporting citations — an edge is defined by its endpoints, and the context names stay on the node — rejected: copying supporting citations onto every edge.
- Intervention names in `AREA[InterventionName]` are always double-quoted, and names containing `"` are rejected — unquoted, "pembrolizumab (KEYTRUDA®)" is parsed as grouping (559 hits vs 43), and an escaped quote matched nothing — rejected: quoting only multi-word values, and stripping quotes.
- `query.cond`/`query.spons`/`query.locn` values are sent raw, and values containing Essie syntax (`"`, `()`, `[]`, standalone uppercase AND/OR/NOT) are rejected with a structured error; the semantics are stated in `meta.search_semantics` — raw keeps the API's synonym expansion (NSCLC: 8601 raw vs 8078 as a quoted phrase), and rejecting syntax stops users or the LLM from changing search semantics by accident — rejected: quoting every value as a phrase.
- A count that does not reconcile with totalCount is flagged (`FetchResult.reconciled=False`, meta warning) rather than raised — the API refreshes daily and can shift during pagination; the chart is still useful when the gap is stated — rejected: a ReconciliationError that fails the whole request.
- Studies are deduplicated by NCT ID across pages, and duplicates are counted in meta — page tokens are not bound to a query, so a repeated record would inflate counts silently — rejected: trusting pages to be disjoint.
- Every page sends identical params, including `countTotal=true` (ignored after page 1) — a single frozen param set is easy to verify and the token cannot be mixed with other params — rejected: sending countTotal on page 1 only.
- The response cache works per page (key = URL + sorted params); when page 1 is a hit, later pages must be hits too, otherwise the fetch restarts live — mixing a cached token with a live fetch could silently return a different result set — rejected: caching only whole fetches, which needs a second key scheme.
- `top_n` keeps the N known buckets with the most trials (union of cohorts, ties in display order) plus the Unknown bucket, with no "Other" bucket, and reports the omitted keys and the trials visible only in omitted buckets — an "Other" count is correct only for mutually exclusive dimensions (it would double-count for countries or conditions); it could be added later for exclusive dimensions only — rejected: an "Other" bucket for every dimension.
- `top_n` with a relation is rejected by the validator — networks have no buckets, and trimming nodes would need its own rules for orphaned edges — rejected: silently ignoring top_n.
- Grouped results across cohorts share one key order, computed by `group_by` over the deduplicated union of trials — reuses the dimension's own ordering rules (rank, key or count) without exposing ranks — rejected: merging per-cohort orders, which cannot recover phase rank order.
- Response encoding uses Vega-Lite-style channels, and networks use Cytoscape-style `{data: ...}` elements with edge ids `<source>--<target>` — renderer-neutral vocabularies most clients already know — rejected: a custom encoding format.
- `meta.interpretation` holds the question, the executed plan and `planned_by` ("structured_fields" until the LLM planner exists) — the reader must know that the question text was not interpreted — rejected: echoing only the plan.
- Records that fail normalization are skipped and listed by NCT ID in meta warnings, with a per-cohort `records_skipped` count — one malformed record must not fail a request over thousands — rejected: failing the request, and dropping records silently.
- Network node sizes are flagged as overlapping (`buckets_overlap=true`) — a trial counts toward its sponsor and every drug it lists — rejected: reporting false because a graph has no buckets.
- Settings come from environment variables (prefix CTVIZ_) via pydantic-settings, which is already a dependency — one typed place for the cap, pacing, retries and cache — rejected: module constants.
- Live tests are excluded by default (`addopts = -m 'not live'`) and run with `pytest -m live` — the default suite stays offline and deterministic — rejected: an environment-variable switch.
- Start dates with no ACTUAL/ESTIMATED type are counted in their period and reported per bucket and in total (`unknown_date_type_count`) with a warning; trials with no start date at all stay in Unknown and are not counted again — 41 of 2518 pembrolizumab trials starting 2015+ are legacy records without a type, and per-bucket counts let a chart style uncertain periods — rejected: treating untyped dates as actual without saying so, and excluding them.
- Dimensions have a separate `title_label` for chart and axis titles ("start year") while `label` stays in warnings ("start date") — the title must state the granularity, but warning text is about the source field — rejected: renaming `label`, which changes warning text.
