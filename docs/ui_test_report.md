## Headline findings

1. **Notices with severity `warning` never appear in the UI (blocker).** Notices with severity `info` render under "Things to know about these counts". Every notice with `severity: "warning"` is in the response JSON but appears nowhere on the page (I searched the DOM outside `<pre>`). Affected: `cohort_subset` (A2), `not_applied` (A6), `cohorts_overlap` (C1, "95% overlap"), `unrecognized_values` (C1), `did_you_mean` (C2), and `status_trend_bias` (C3). Every case that was meant to protect the user from a misleading chart therefore shows the chart with no caveat. In C2, a user sees "2 studies" for "pembro" and is never told that pembrolizumab has 2,642.
2. **The lead-sponsor chart breaks for large cohorts (blocker).** C5 "Breast cancer studies by lead sponsor" returns 2,755 bars. The chart draws them into a canvas 66,210 CSS px tall, which is 132k device px at DPR 2 and over Chrome's canvas limit. The user sees an empty white box with a broken-image icon. The UI needs a display cap or an automatic top N for high-cardinality dimensions.
3. **Loading gives almost no feedback (major).** A query takes 0.9–20 s, for example about 20 s for C1. During that time the previous chart stays on screen at full opacity. The only cue is a disabled Ask button, which is usually scrolled out of view. I mistook a stale chart for the new result once (see [C1_loading_state_stale_result.jpg](ui_screenshots/C1_loading_state_stale_result.jpg)).

## Console and network errors

- **Console:** no errors, warnings or logs from page load through the last case, on both :8000 and :8765.
- **Network:** every ctviz `POST /query` returned 200 or the expected 422. There were no 5xx responses from ctviz.
- The B3 first attempt on :8000 failed with "The request did not reach the server: Failed to fetch". That was the server being swapped out, not a ctviz bug. The UI handled it correctly, and the extension's network panel logs refused connections as "503".
- **Payload size:** A6 returned 3.1 MB before server-side trimming and C5 about 1.86 MB. Both rendered in the developer `<pre>`. A 2,755-bar chart is the real problem in C5 (see the fix list).
- **External dependency:** ECharts loads from cdn.jsdelivr.net at runtime, so the demo fails offline or behind a strict proxy.

## Visual review (frontend reviewer)

1. **Hierarchy:** h1 is 20px and the result title is 19px, almost the same. The answer should be the loudest thing on the page, but the question form and chips get more visual weight than the result.
2. **Key facts:** they run together as a log-like line of `label: value` fragments separated by wide gaps and wrapping unpredictably ("trastuzumab: based on 1,321 retrieved records…"). A small definition grid or a "Based on N studies · as of 16 Oct" subtitle would read far better.
3. **Spacing:** each section sits between hairline rules, which reads as a stack of log panels. The rules plus the 24–32px gaps give equal weight to everything.
4. **Colour discipline:** colour is mostly semantic: blue for data, grey for not applicable, light blue for Other and in-progress, hatching for unknown, red only for errors. Two leaks: grey NA bars lose the series colour in grouped charts, and the two sponsor-network node kinds use blue and orange with no semantic reason.
5. **The missing amber tier:** there is no visible warning style at all. Caveats come in two loudnesses only, plain bullets or a red error box. Severity `warning` needs an amber callout above the chart. This is also the fix for root cause #1.
6. **Typography:** `tabular-nums` is set globally, which is good, and the numbers align. NCT IDs should be monospace. The select text is 15px against 13px labels and 13px chips, a mismatch. Value labels inside the canvas are about 11px and low-contrast for "Other".
7. **Ops-console tells:** config constant names in user notices (`MAX_NETWORK_NODES=50`, `NETWORK_MAX_RESPONSE_BYTES`, `meta.network.excluded_terms`, `ACTUAL/ESTIMATED`, "Bucket '2026'"), raw Pydantic errors, raw enums in citations (`PHASE2`), and the LLM model name in "How these numbers were made".
8. **Copy consistency:** "trials" (chips, notices) and "studies" (titles, axes) are used interchangeably. Plurals are off ("1 withdrawn studies", "1 are listed"). Thousands separators are inconsistent ("2048" vs "2,048").
9. **Charts:** the axis-title and label clipping (A4) and the network clipping at the top (A7, chip 7) suggest the grid margins are too tight. The bar thickness doesn't adapt (C2's two bars are 30px tall).
10. **The three changes that would most improve it:** (a) render warning-severity notices as an amber callout directly under the title; (b) add a real loading state: dim or replace the old result, with a spinner and elapsed time, and keep the Ask button in view; (c) rewrite notices for analysts: no constant names, consistent "studies", proper plurals and separators, and a compact key-facts subtitle.

**Fixed:**
- Fix 1 (A2, A6, C1, C2, C3). Warning notices were built into a container that was never un-hidden. Errors now appear as red banners and warnings as amber banners, both above the chart in response order; info notices stay below.
- Fix 2 (C5). The server shows the 50 most frequent values (`MAX_BARS`), with an Other bar where it is exact, a `readability_cap` warning and "(top 50)" in the title. The page also caps the chart at 4,000 px and 200 bars.
- Fix 3 (C1). While a question is being answered, the previous result is dimmed, elapsed seconds are shown and the button is disabled.
- Fix 4 (A6, A7, E3 chip 7). The network fits its box and has the same layout on every run. Only the 12 largest nodes and the hub are labelled, and overlapping labels are hidden.
- Fix 5 (D3). An empty question shows an inline message and sends no request.
- Fix 6 (A4). The month-axis title and the first tick are no longer cut off.
- Fix 7 (E1). Citations show NCT IDs in monospace, the field path, and values such as "Phase 2 (PHASE2)".
- Fix 8, partly (A6, C5). Network and size-limit notices no longer name settings.

**Remaining:**
- In the dense hub of a network, node marks can still cover labels.
- Structured-only queries need a question, because the API requires one. The page now says so.
- Fixes 8–13 except as noted above: other notice copy, the key-facts layout, the hue of grouped not-applicable bars, the first-click flake of the pasted-JSON Render button, print, and the CDN dependency.
