## Notes on cases

- **colloquial_abbreviation_comparison**: Verbatim names are the designed behaviour: rule 1 exists so the LLM never substitutes a name it guessed, so a plan with drug=pembro and drug=nivo by phase is the correct planner output. Listing them in unhandled_terms would be wrong, because they are applied as filters. The user-facing gap ("pembro" matches almost nothing) belongs to a zero-match "did you mean" step at retrieval time (README section 9), not to the planner.
- **chinese_question**: "Pembrolizumab trials per year" in Chinese. Rule 1 forbids translating a name, so a plan is only useful if the model maps the Chinese name to the registry name; declining or asking back is also acceptable. A plan that copies the Chinese name verbatim is a miss: it would match no registry record.
- **fewest_is_not_ranking**: The id predates the fix and is kept because the cached paraphrases are keyed by it. Until 2026-10-18 the expectation was "no ranking" (top_n null), because the boolean ranking_intent could only mean "most" and gpt-5-mini set it for "fewest", showing the 15 largest countries. "fewest" is now its own direction, trimmed to the bottom N.

## Ranking fix (2026-10-18)

`LlmPlanDraft.ranking_intent` (a boolean that could only mean "most") was replaced by
`ranking_direction: "most" | "fewest" | null`. The prompt asks for "fewest" only for fewest,
least or lowest wording. Code turns the direction into the plan:
- "most" sets `top_n`, as before;
- "fewest" sets `bottom_n`: the N known buckets with the fewest trials. Unknown and
  Unrecognized are not ranked but are still shown. The title ends "(bottom 15)", and the
  assumption says that values with no matching trials have no bucket and cannot appear.

The ranking cases were then re-run first: `geographic_ranking_without_number`,
`fewest_is_not_ranking` and `geographic_top_n_phase`, each with its 2 cached paraphrases,
`--repeats 3`. They passed 27/27 runs on both models (`gpt-4.1-mini` mean 1.0 s,
`gpt-5-mini` 4.8 s). The full run above was done afterwards on the same prompt.

## Limitations

- 25 seed questions detect systematic failures (a query class the planner cannot
  map, a rule it ignores), not statistically robust accuracy: one miss moves a field by
  about 4 points, and a perfect score does not mean the planner is always right.
- Results are for one prompt version on one day. Model outputs vary between runs at the
  same settings, providers update models behind the same name, and any change to the
  prompt, few-shot examples or registry descriptions needs a new run.
- Questions were written by the developer of the prompt, so they share its vocabulary;
  real users phrase questions differently and misspell names.
- Latency is wall-clock time from one machine, including the network and any retry.
- The paraphrase cases were generated by an LLM (the configured planner model), not by
  real users, and each inherits its seed's expectations unchecked: a paraphrase that
  drifted in meaning would be scored against the wrong answer. They test robustness to
  rewording, not to the vocabulary or mistakes of real users.
